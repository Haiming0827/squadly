# 根 App 的桌面照片绘制与点击验收

2026-10-31（Asia/Shanghai）。用户解锁 Mac 后，使用 Device Hub 实际操作普通根 App `com.squadly.squadly`，未运行测试宿主替代界面，也未注入 WidgetKit 图片。无生产代码变更。

## 本次实际通过

- A（iPhone 17 Pro / iOS 26.5）与 B（iPhone 17 / iOS 26.5）普通终止后启动均恢复现有登录并进入真实会话首页，没有重新登录。
- 初始绑定是已撤回照片的权限反例队，A 桌面显示空状态、B 关闭预览显示隐藏。普通 JWT 查回绑定队原子头为空；另一个保留夹具队有有效合成照片，排除“有图但前台丢图”的误判。
- 在「小队 → 我的小队」选择保留合成照片队，进入「小队桌面组件」，主动重绑；A/B 设置页均确认重绑后预览为关闭。
- 开启预览，经生产 service/repository 实际读取 staging 合成照片，设置显示“照片已交给系统更新”。A 回 Home 后中尺寸组件、B 回 Home 后小尺寸组件都实际显示橙色合成 JPEG 与“点开回拍一张”。截图观察与缓存成功分开记录。
- A 在照片区域执行真实桌面点击，进入「回拍照片」，受众为绑定的合成照片队。模拟器相机不可用给出中文提示；没有发送新照片。

还未验证：本轮全新系统添加、自然 15 分钟到期、关闭预览后的实际桌面清图、退出/离队/隐藏在各设备桌面清图、锁屏/重启/签名真机、实际 PHPicker 选择发送与不同作者完整往返。既有两个尺寸实例已经存在，不能把本次重绑说成新添加通过。
