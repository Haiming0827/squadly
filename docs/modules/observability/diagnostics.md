# 错误诊断与隐私边界

状态（2026-10-26）：已接入 Dart/Flutter 错误入口、主动同意开关、账号隔离的本机授权设置、白名单过滤和 Sentry envelope transport。用户尚未创建 Sentry 项目，当前构建没有 DSN，开关显示「此版本暂不可用」，不会上传。原生崩溃、云端收件和符号化验收仍未完成，M5 不能据此标记完成。

## 授权和发送规则

- 默认关闭。配置有效 HTTPS 公共 DSN 后，「我的 → 发送错误报告」仍须弹窗确认「同意并开启」；写入本机授权成功后才发送。关闭立即停止新提交，并废弃尚未交给 transport 的旧队列。
- 授权按账号保存；身份恢复前不能启用历史授权。确认退出/切换账号时撤销原账号授权；同账号异步加载不当作登出，旧账号延迟写入不能修改新账号设置。缺配置、配置错误、设置读取/保存失败都保持关闭。
- 只发送启用后的新错误，不补发关闭期间的错误。队列仅在内存，最多 8 项，不落盘。应用入口配置采样 1；基础 reporter 默认总开关、授权和采样均关闭，测试覆盖开关/采样/撤销。
- 已交给 transport 的网络请求无法靠关闭开关撤回；Sentry 服务端保留期限、访问权限和撤回流程须在项目创建并启用真实上传前明确。

## 过滤边界

诊断不得包含消息正文、个人素材、健康/财务值、路线或密文、联系方式、用户/Squad/记录标识、令牌或密钥。`DiagnosticSanitizer` 重建白名单载荷，禁止直接序列化原异常、scope 或任意嵌套 JSON。

允许的载荷只有随机事件 ID、诊断发生时间、受控错误类别、数字 App 版本、部署环境，以及来自静态源码目录白名单的 Dart 文件/行/列（最多 20 帧）。丢弃异常消息、动态类型名、函数名、外部或绝对路径、请求信息、breadcrumbs、用户上下文、tags、extra、附件、截图、视图层级、录屏、日志、性能 span 和设备标识。

## SDK 和 transport

固定使用纯 Dart `sentry 10.2.0` 的公开事件/envelope 编码 API；不初始化全局 Sentry、不链接 `sentry_flutter` 原生插件，也不启用原生 SDK、会话、附件、Replay、日志或自动 scope。HTTP 客户端仅接受已经过滤的 `DiagnosticEvent`，禁止重定向，发送和响应读取有超时；不输出服务端响应正文。

这只覆盖 Dart/Flutter 错误事件，不能宣称已经采集进程被系统终止、原生崩溃或卡死。2026-10-20 的 `sentry_flutter 10.1.0` 试解析曾导致 JNI 降级，该试验已撤销；本轮保持既有 JNI 依赖基线。将来接入 Flutter 原生 SDK 必须单独审核所有出站通道，参考官方 [过滤说明](https://docs.sentry.io/platforms/dart/guides/flutter/configuration/filtering/) 与 [配置项](https://docs.sentry.io/platforms/dart/guides/flutter/configuration/options/)。

## 本地验证与剩余工作

本地测试截获实际编码的 envelope，确认仅一个白名单事件、无消息/财务/健康/凭据样本；覆盖无 DSN、错误配置、默认关闭、明确同意/取消、持久化失败、授权撤销、延迟恢复和账号切换。`submitted` 仅表示 sink 接受提交，不是云端收到事件。
