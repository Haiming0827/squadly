# A8 接收者隐藏与基本举报

2026-10-31，先定义后实现。隐藏是接收者自己的偏好，不撤回作者照片、不改变队友视图；举报不自动处罚或向队友公开举报人。

- 增加 service-only 的隐藏事实 `(user_id,squad_id,message_id)` 和每账号/队伍的单调可见性计数。仅当前队员能通过受控 RPC 隐藏该队照片，重复请求幂等；账号、队伍或消息删除时级联清理。没有任意 user_id 参数。P0 不提供自动恢复，操作前明确“仅对你隐藏”。
- 会话保留照片消息墓碑 `hidden=true`，不返回图片；照片墙、父照片查询和组件照片头排除本人的隐藏项，媒体读取再次拒绝。其他成员的投影不含此隐藏标志。离线缓存只保存墓碑元数据，不保存像素。
- 组件版本是 `公共照片版本 + 本人的可见性计数`，均单调非负，用 bigint 范围十进制字符串返回。两者均不回退，所以同一账号观察的结果不乱序；计数溢出失败关闭。隐藏不改变全队公共版本，不向其他成员透露隐藏事件。App Group 仍按账号 scope 隔离。会话/组件在本机确认隐藏时立即丢弃像素并触发同队刷新，迟到取图不得恢复旧图；其他设备只能在提示/下次在线复核时更新，现有租期和平台限制保留。
- 只向隐藏者自己的已登记 APNs 设备生成无内容 photo_sync；不广播给队友，沿用 A8 generation/lease 完成规则。原生无需新载荷，仅取本人过滤后的新头。未配置 provider 继续不派发。
- 举报只接受 spam/harassment/privacy/other 受控原因，不能举报自己的照片；必须是当前可访问 Squad 的照片，匿名、跨队和离队拒绝。事务中保存唯一 `(reporter,message)` 记录并隐藏照片，重复确认不复制案例。没有自由文本、截图、原图、健康或位置上传，不扩大内容受众。
- 举报记录只有 service_role 可查/处理；客户端只得到 reported/hidden 确认，不读取工单明细，不公开计数或举报人。服务端运维需按真实案例处理并记录状态；本轮不会宣称自动审核、处理时限或完整治理后台已上线。消息/队伍/举报者删除级联清理，不另行保留图片证据。
- 照片网关动作只接受原 Squad/消息和受控原因，使用原用户 JWT 调 RPC；服务端 Key 不代替用户决策。UI 通过 domain 接口调用，失败不显示“举报成功”；账号/页面/会话变化拒绝迟到结果。隐藏/举报不推进已读。

验收覆盖：A/B/C/匿名、同队/跨队、重复隐藏与举报、自己举报拒绝、隐藏者与作者不同投影、媒体/照片头/分页/深链拒读、个人计数与公共发布并发、离线墓碑、控件确认/失败/账号切换、小屏。必须分别留本地、真实 staging 和 iOS 证据；不将 mock 成功当平台通知或人工处理通过。
