# 生产 provider 与原生续期协同验收

2026-10-31。接续同一成员的 SDK→原生正向验证，进一步覆盖生产认证恢复、离线 SDK 事件、缓存生命周期与组件 provider 的共同运行。

本地组合用例使用实际 SDK、生产 AuthNotifier/repository/资料恢复和组件 lifecycle，仅 SDK/PG transport 与原生方法通道为可控外部边界。原生替身严格检查代次，使过早正向同步会拒绝票据；测试 SDK 初始恢复、续期事件、退出与换账号竞争。

staging 继续使用普通 A/C 临时两人小队及合成照片。独立宿主只在 CloudBase app binding 处注入同一个受控 C Auth 实例和原环境 config；不手动组装续期控制器，不替换 currentUser/AuthNotifier/repository/SDK 事件或 PG HTTP。离线身份来自实际 SDK 事件，当前用户必须经真实 PG profile 恢复。后台生命周期状态明确由测试设置；缓存实例设为 null，避免修改其他设备验收历史。

原生先启动取图等待；随后启动与 App 根组件相同的 provider。SDK 实际刷新、认证资料恢复和原生票据必须协同成功；服务端成员/头/媒体复核及缓存写入、重复不续租、不推进已读仍使用已有正向断言。认证材料只经过 0600 独立宿主输入/输出，完成后收回 C 轮换材料并清理本次临时云端资源。

这验证生产 provider 的组合行为，未执行 main() 的磁盘 SDK 恢复、路由/系统前后台切换或实际 APNs；不将注入后台状态和受控 SDK 实例记为完整正常冷启动或真机通过。

清理恢复补充：媒体循环引用清除的 HTTP 结果可能不确定，但数据库写入已提交。作者撤回成功后须在 0600 台账持久化确认，再解除循环引用；恢复时不得对已清引用的媒体重新执行撤回。旧台账可从已成功的作者撤回记录恢复检查点。失败只记录接口类别、异常类和 HTTP 状态，不记录响应正文；最终报告保留历史失败及恢复后的实际空行/404验证。
