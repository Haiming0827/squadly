# 照片上传传输合同与 413 修复

2026-10-31。用户在普通根 App 从系统相册选择照片并确认后，反复看到“照片服务暂不可用 / 已保存待发，联网后会继续重试”。先验证两台模拟器 URLSession：Apple HTTPS=200、CloudBase 无鉴权身份接口=401、照片 GET=405，均可联网。B 当前 SDK 普通会话身份/头/小图读取及小图发送/回拍返回200。

## 已复现的原因

1,451,294 字节的 1600×1200 合成 JPEG 通过当前文本 JSON POST 普通发送/回拍均得到 HTTP413。131,072 字节文本请求也被网关以 `EXCEED_MAX_PAYLOAD_SIZE` 拒绝。官方[具体错误说明](https://docs.cloudbase.net/error-code/EXCEED_MAX_PAYLOAD_SIZE)区分云函数文本请求100KB、其他类型6MB；不能将概要表的6MB理解为JSON也允许6MB。

只对照片 worker 改用 `application/octet-stream`、保持同一 JSON 信封原始 UTF-8 字节后，大图普通发送/关联回拍均200。误将 PG RPC 也改成二进制曾返回404；PG接口继续JSON，此失败未算照片传输通过。已有 worker 的 `isBase64Encoded` 解析兼容网关二进制事件，无需新桶、新权限、SQL或改变媒体字段。

## 修复边界（先定义后实现）

- 只有 `publish` 的媒体 HTTP 请求使用 octet-stream，data 明确为 JSON UTF-8 字节；不要改 PG REST、Auth、原生 metadata 请求或其他业务 API。
- 信封中的账号、Squad、父消息、nonce、源摘要和已确认派生 JPEG 不变。网关二进制编码不是加密；TLS、JWT、GRANT/RLS、服务端重绘和私有对象权限继续执行。
- 2MiB 图片上限及1600px不降低；不以压到几十KB牺牲画质来规避网关限制。UTF-8信封及网关事件双层编码仍须在已有服务端有界解析与平台6MB内。
- 对已确认加密待发记录使用原字节/原nonce重试，不能要求用户丢草稿或重新选图。
- 未知413应给出“请求过大/更新应用重试”的安全错误；非网络故障不能一律声称“联网后”解决。仅实际 NetworkFailure 使用联网重试提示，其他待发状态显示可稍后重试。
- 回归必须使用超过100KB的真实可解码JPEG，检查Dio实际发送流、网关二进制事件解析、同nonce/父身份；最终以普通根App的系统相册/既有待发实际发送验证。不能用4×3小图通过代替真实照片。

诊断只记录状态、受控错误码、尺寸/字节数与耗时，不输出照片、SDK材料、用户/消息ID、对象路径或完整服务端正文。部署配置不因本修复扩权，系统日志保持关闭。
