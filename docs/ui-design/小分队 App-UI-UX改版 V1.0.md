# 小分队 App｜UI/UX 改版 V1.0

> **文档用途**：供本地 Agent、产品、设计及开发人员读取并执行的 UI/UX 改版需求文档。
>
> **产品定位**：综合生活协作型。
>
> **核心设计原则**：橙色用于品牌识别和关键操作，不用于统一渲染整个界面。页面背景与卡片保持中性；插画、简画、照片按业务场景灵活配色。
>
> **产品愿景**：让朋友、伴侣、家人和兴趣搭子一起规划生活、完成目标、记录成果。
>
> **重要提醒**：本文件以对话中确认的 V1.0 方案为准；其中页面示意、数据、时间为原型演示，非实际业务数据。文字线框是结构描述，不是已实现界面。设计 Token 需在目标平台做对比度和可访问性验证。

## 一、产品定位与视觉原则

### 1.1 品牌与设计风格

- 产品：小分队
- 品牌口号：**好玩的事，一起做。**
- 视觉关键词：**简洁、温暖、自然、有参与感、可信赖**。
- 品牌主色（Brand Orange）：`#FC6634`，参考现有小分队 App 图标。
- 交互主色（Action Orange）：`#C2411A`，用于承载白色文字的主要按钮等高对比度交互位置。
- 品牌色不等于所有内容都要染成橙色。应以白色、浅灰和深灰组织信息。

### 1.2 橙色的使用边界

| UI 元素 | 橙色使用策略 | 设计要求 |
|---|---|---|
| Logo、品牌 Icon | 必须/优先 | 保持现有品牌橙的识别性 |
| 主要按钮 | 使用橙色体系 | 采用满足文字对比度的交互橙 |
| 底部导航选中态 | 使用 | 选中图标与文字；其余中性色 |
| 功能图标 | 适量使用 | 关键入口强调；普通入口中性 |
| 进度条 | 可选择 | 关键进度可以用橙色，不能表示所有状态 |
| 普通卡片 | 不默认使用 | 白色或浅灰等中性色 |
| 页面背景 | 不使用橙色大色块 | 白色、浅灰为主 |
| 正文文字 | 不使用橙色作常规正文 | 黑色、深灰与次级灰 |
| 插画、简画 | 不限制配色 | 蓝、绿、紫、黄等按场景选择 |
| 旅行、美食照片 | 不限制配色 | 保留图片真实色彩 |
| 成功 / 警告 / 错误 | 不统一用橙色 | 使用语义色区分 |

**反模式**：避免同一页面出现大面积橙色背景 + 橙色卡片 + 橙色图标，造成视觉疲劳和层级混乱。

## 二、信息架构 IA V1.0

### 2.1 一级导航：保留四个 Tab

```text
小分队 App
├── 会话（沟通）
│   ├── 消息列表
│   ├── 小队群聊
│   ├── 计划讨论
│   └── 系统通知 / 搜索
├── 小队（成员与共同空间）
│   ├── 小队列表 / 空状态
│   ├── 小队首页
│   ├── 成员与邀请
│   ├── 小队动态
│   └── 小队管理
├── 计划（目标与任务执行）
│   ├── 计划首页
│   ├── 创建计划
│   ├── 计划详情
│   ├── 任务与打卡
│   ├── 计划模板
│   └── 完成回顾 / 历史记录
└── 我的（个人身份与隐私）
    ├── 个人主页
    ├── 参与记录
    ├── 个人私密数据
    ├── 共享权限
    └── 外观和设置
```

| 主导航 | 用户目标 | 页面核心内容 |
|---|---|---|
| 会话 | 讨论与沟通 | 最近消息、群聊、计划关联讨论 |
| 小队 | 找到一起做事的人 | 成员、共同空间、队伍动态 |
| 计划 | 推进具体事项 | 进行中计划、任务、进度、模板 |
| 我的 | 管理个人信息及数据 | 个人记录、身份、隐私、设置 |

**架构边界规则**：

1. **小队是协作空间，计划是执行对象，会话承载讨论，个人数据属于用户自己。**
2. 小队首页应展示团队整体状态、成员、共同目标摘要；计划页承担任务操作、进度与计划管理，避免两个页面重复展示相同列表。
3. **所有计划必须关联当前小队**：计划可选「仅自己可见」，但该选项只控制可见范围，不解除小队关联；创建或加入小队仍是前置流程。此规则按 2026-10-18 确认结果更新，取代本建议早期允许独立个人计划的草案。
4. 对敏感数据实行默认私密：个人健康记录、个人资产不可因加入小队而自动公开；共享应有清晰的授权范围和撤销入口。

### 2.2 统一四类场景模型

所有场景共享基础协作模型：**计划 → 任务 → 成员 → 进度 → 成果**。

| 场景 | 核心功能 | 颜色/素材原则 |
|---|---|---|
| 健身 | 目标、打卡、训练与共同挑战 | 插画可用绿、蓝等运动色彩 |
| 理财 | 预算目标、储蓄计划、共同支出任务 | 强调私密与共享边界；界面可信清晰 |
| 旅行 | 行程、清单、成员分工、旅行记录 | 风景/照片保持自然色彩 |
| 美食 | 餐厅候选、聚餐计划、投票、到访记录 | 使用真实食物与餐厅图片的色彩 |

业务场景可有不同封面/插画及辅助色，但导航、按钮、布局和组件形态统一。

### 2.3 三条核心用户路径

**路径 A：首次建立协作**

`进入小队 → 创建/加入 → 邀请成员 → 创建第一个共同计划`

**路径 B：日常计划执行**

`打开计划 → 查看待办 → 完成任务 → 更新进度（同步给成员）`

**路径 C：私密数据共享**

`个人记录 → 选择共享范围 → 确认授权 → 管理/撤销共享`

### 3.1 七个页面总览

### 3.6 其他页面的结构要求

**S01 会话**：页面顶部标题与搜索；最近会话和分类；小队消息及与计划绑定的讨论可以分辨；支持未读提醒。

**S03 小队首页**：标题/封面（素材自由配色） → 成员及邀请 → 小队概况和共同计划 → 最近动态；不与计划首页重复承担完整任务管理。

**S07 我的**：头像/昵称及个人资料 → 参与过的小队和成果记录（真实数据存在时） → 账号、数据与隐私 → 外观、通知、帮助和退出登录。个人私密数据不可出现在小队动态中。

### 3.7 页面状态矩阵（所有关键页面均要考虑）

| 状态 | 行为要求 |
|---|---|
| 首次使用 | 展示价值、明确下一步操作 |
| 空状态 | 解释无内容原因，给出主要 CTA |
| 正常状态 | 优先展示最重要内容和主要行动 |
| 加载中 | 骨架屏或轻量反馈，避免大幅布局跳动 |
| 请求失败 | 说明问题并提供重试 |
| 网络异常 | 区分离线可执行和暂不可执行操作 |
| 权限不足 | 不泄露私密数据，解释访问限制 |
| 更新同步中 | 提示状态并防止误认为已成功同步 |
| 已完成 | 进度或成果回顾清楚呈现 |

## 四、基础组件规范 Design System V1.0

### 4.1 颜色 Token

#### 品牌和交互色

| Token（建议命名） | 色值 | 用途 |
|---|---|---|
| `color.brand.primary` | `#FC6634` | Logo、品牌标记、强调装饰 |
| `color.action.primary` | `#C2411A` | 主按钮、重要可点击文字、选中交互元素 |
| `color.brand.tint` | `#FFF1EB` | 少量选中态背景、轻强调背景 |

**对比度约束**：原品牌橙 `#FC6634` 与白色文字的对比度约为 2.96:1，不适合作为普通小字白色按钮的背景；含文字的主按钮建议使用更深的交互橙（例：`#C2411A`），发布前需按 WCAG 等适用标准重新检验各种文字字号及状态的对比度。

#### 中性色

| Token | 色值 | 用途 |
|---|---|---|
| `color.surface` | `#FFFFFF` | 卡片/主要表面 |
| `color.background` | `#F7F8FA` | 页面背景 |
| `color.border` | `#E5E7EB` | 分割线和边框 |
| `color.text.primary` | `#1F2329` | 标题和正文 |
| `color.text.secondary` | `#667085` | 辅助文字 |
| `color.text.muted` | `#98A2B3` | 低强调内容 |

#### 语义色

| Token | 色值 | 用途 |
|---|---|---|
| `color.status.success` | `#198754` | 已完成/操作成功 |
| `color.status.warning` | `#B76B00` | 警告、注意 |
| `color.status.error` | `#C83232` | 错误、失败 |
| `color.status.info` | `#2563EB` | 普通系统提示 |

**特别说明**：状态色只表示对应语义，不能被品牌橙统一替代。深色模式需要独立定义语义 Token，不应简单反转图片/品牌色。

### 4.2 字体、间距、圆角与触控目标

| 元素 | 起始规格 |
|---|---|
| 页面水平内边距 | 16–20 |
| 间距阶梯 | 4 / 8 / 12 / 16 / 24 / 32 |
| 页面大标题 | 26–28sp，Semibold |
| 模块标题 | 20sp，Semibold |
| 卡片标题 | 16sp，Medium |
| 正文 | 14–16sp，Regular |
| 辅助文字 | 12–13sp |
| 主按钮视觉高度 | 48–52 |
| 卡片圆角 | 16 |
| 按钮圆角 | 12–14 |
| 常规图标 | 24 |
| 最小触控目标 | iOS 44pt；Android 48dp |

数值为初始设计指导，不同端需根据 pt/dp/sp 与平台设计指南适配；支持系统字体缩放、动态字体、长文本和无障碍阅读。

### 4.3 十个基础公共组件

| Component | 用途 | 必须设计的状态 |
|---|---|---|
| `AppTopBar` | 标题、返回、更多操作 | 默认/返回/更多 |
| `BottomNav` | 四个一级导航 | 选中/未选中/未读 |
| `Button` | 主次按钮 | 默认/按下/加载/禁用 |
| `TeamCard` | 小队信息摘要 | 正常/空/加载 |
| `PlanCard` | 计划摘要及进度 | 进行中/完成/逾期 |
| `TaskRow` | 任务行与勾选 | 待完成/完成/同步中 |
| `MemberAvatarGroup` | 显示协作成员 | 少量/数量溢出/缺失头像 |
| `ProgressBar` | 目标进度 | 0–100%/无数据 |
| `EmptyState` | 空白页面引导 | 无小队/无计划/无消息 |
| `PrivacySelector` | 数据共享范围 | 私密/小队/指定成员 |

### 4.4 按钮视觉与图标规范

- **PrimaryButton**：深橙底（建议 `#C2411A`），白色文字，突出单页面的首要行动。
- **SecondaryButton**：橙色描边与文本，背景中性，适用于次要行动。
- **DisabledButton**：中性灰，状态明确，禁止与正常按钮混淆。
- **选中图标**：交互橙；**普通图标**：中性灰；**成功/错误**：语义色。
- 图标统一一套线性风格、视觉尺寸、线宽、触控区域；必要的实心状态应有一致规则。
- 旅行、运动、美食等插画/照片不使用统一橙色滤镜，避免损伤场景表现力。

## 五、分阶段设计任务与交付计划

### 5.1 建议时间规划（设计 4 周）

## 六、给本地 Agent 的实施说明

### 6.1 项目执行优先级

1. **先信息结构，再视觉细节**：保留四 Tab，不把小队和计划做成两套重复任务列表。
2. **先 P0 流程，再广泛铺页面**：小队空状态/加入、计划创建、计划首页、任务详情是最优先的可用性验证对象。
3. **沿用品牌图标橙色，而非满屏橙色**：`#FC6634` 为品牌识别主色；关键白字 CTA 使用可读性更好的深橙（如 `#C2411A`）。
4. **插画保持多彩和场景感**：可以有蓝天、绿地、食物原色。内容丰富，但组件视觉规范一致。
5. **先建立复用基础**：公共按钮、导航、卡片、任务行、状态组件及主题变量统一实现。
6. **状态完整**：不要只实现有内容的成功状态；首次使用、加载、离线、同步失败、无权限均要处理。
7. **保护隐私**：健康和资产记录默认个人可见，成员身份不自动产生读取权限。

### 6.2 推荐的下一交付版本

在 V1.0 信息架构确认后进入 **V1.1 关键页高保真**：

- 小队空状态
- 小队首页
- 计划首页
- 计划详情

先串联这些页面形成可点击原型并做真实任务测试，再扩展其他复杂业务功能。
