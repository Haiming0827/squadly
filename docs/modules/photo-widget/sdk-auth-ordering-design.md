# SDK 会话改写的单实例顺序边界

2026-10-31，后台续期的前置安全合同。已用实际安装 SDK + 可控 transport 复现：旧 getSession 刷新尚未返回时，App 退出完成；随后旧刷新把 SDK currentSession 恢复为原账号。单纯丢弃 UI 响应不能阻止 SDK 内部改写。

- 每个 SDK Auth 实例共享一个 Dart 顺序队列。所有可能间接触发刷新/会话写入的 SDK 调用，包括 getSession/getUser、登录/退出/OTP/修改资料及 SDK 返回的验证闭包，都经同一队列；不只约束新增后台调用。不改 SDK 私有存储或复制 refresh token。
- 同一代的 getSession 共享一次读取。显式认证写入在排队时立即提升代次；之前请求即使得到有效旧 token，也返回受控 session_changed，不交给新的 PG/照片请求。排队后的读取等待认证写入完成，读取新的 SDK 事实。
- 认证 SDK 调用完成后释放队列，再做 PG profile HTTP，避免仓库调用 token reader 时重入死锁。密码恢复的未登录检查、验证及其临时会话退出作为同一 SDK 事务，其他读取不能插在两者之间。
- 排队任务开始前可检查调用者是否仍有效/在预算内；过期任务不再启动 SDK。已经开始的 SDK 网络不能靠 Dart timeout 假装取消：其真实完成前仍持有顺序边界，后续登录/退出等待它结束。UI 已有 loading/代次/撤权仍须先执行，避免等待期间显示旧照片。
- 退出成功时丢弃全部待验证闭包，包括邮箱变更与密码设置，旧页面不得再调用前账号的 SDK 验证器。
- SDK 返回错误或抛出异常不会毒化后续队列。队列按实例弱引用，不存 token、口令或请求正文，不加第二个认证事实源。
- 此合同仅约束当前 Dart isolate 的同一 SDK Auth 实例；不得据此启动另一个无协调 Flutter engine 来刷新同一账号。原生保持短期 access JWT。通知交接须等待这些边界验证通过，再使用既有 engine 和同一 SDK 实例。

验证：旧刷新/退出竞争、旧刷新/新登录竞争、旧读取拒交 token、新读取在认证之后、单代 coalesce、错误后恢复、预算取消、密码恢复临时会话隔离；原生/SDK现有回归与实际C账号SDK续期仍须通过。此前置实现不代表 APNs 或长时间后台链路完成。
