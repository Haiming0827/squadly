# iOS 组件与 SDK 会话恢复顺序

2026-10-31，冷启动回归先复现再修复。有效缓存被启动 `reset:true` 清空的测试已失败；只去除初始无条件重置后通过。此文定义后续协调，不宣称系统冷启动通知或长时间后台续期已通过。

- 区分 SDK 初始恢复、资料尚在恢复、已确认账号、明确拒绝。初始 SDK 尚无结论时不把 null 当退出；不续缓存、不读新 JWT、不启动取图。初始恢复不能无限续租，原生既有 JWT/照片绝对期限照常生效。
- 收到有效 SDK 本地身份但资料未完成时，只按该身份/最短绝对期限同步原生 scope。相同账号/期限是无变化操作，保留原缓存与原生在途任务；不同账号/期限由原生清图并换代，不接受旧写入。不得借恢复阶段建立新的私有凭据。
- 资料确认与 SDK 身份、有效期限一致，且 App 前台时才走既有 service 的资格/头/下载复核和私有 JWT 桥。后台恢复不启动第二套前台下载，也不在启动时替换原生正在使用的同一凭据。回到前台再按现有权限更新。
- 明确退出、认证操作中、SDK 拒绝/错误、资料错误或身份不一致立即清会话/像素/凭据。自然到期时，仅可保留同 scope 已存在的过期恢复引用，清像素与私有 JWT，不能由已退出状态建立引用或授权取图；见[预算内交接](background-renewal-design.md)。认证 pause 与初始恢复须可区分。所有本地变更按顺序完成，网络补取不能阻挡后来的撤权清理。
- 凭据控制器把 clear/reset 作为 prepare 的异步屏障：较早 clear 未完成时，后来的准备和提交必须等待；旧 SDK 返回仍按 ticket/账号/代次拒绝。网络请求不持有屏障，不把退出排在长 HTTP 之后。
- 会话期限变动必须来自 SDK 的绝对期限/JWT exp，不延长旧 token 或像素。原生仍只保存 access JWT。预算内 SDK 交接按专门合同实现与验收；不将回到前台能恢复当作关闭 App 数天仍更新。

验证要求：ready 冷启动保留有效原生副本直到服务端结果；初始延迟/SDK 同账号/不同账号；明确退出/错误/认证暂停；慢 clear 与新 prepare；网络慢于撤权；后台不重复前台取图；真实原生双进程恢复，SDK 超期与跨账号竞争单独验证。保持 App Group 无凭据、扩展无网络/Keychain代码，APNs 仍未配置时不启用平台派发。

SDK 长期恢复前置修复：本轮已用实际安装 SDK + 合成拒绝刷新 transport 复现 `getSession` 成功仍返回过期旧 token。应用 PG token 读取边界必须再次校验 subject/SDK user、绝对 JWT exp 和 SDK expiresAt 最早值；失效或不一致抛受控错误，不把旧 token 当作续期成功。离线身份解析复用同一校验，不把解析当签名验证，不导出 SDK refresh token。此修复不等于已实现原生后台 SDK 续期。
