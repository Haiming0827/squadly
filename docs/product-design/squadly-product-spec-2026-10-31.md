# Squadly 产品规格书

规格版本：V1.2 工作稿。更新：2026-10-31（Asia/Shanghai）。承接[产品设计 V1.1](squadly-product-design-v1.1-2026-10-27.md)，把目标合同与当前实现分开；本稿没有改变既定技术栈或授权边界。[完成情况](squadly-feature-status-2026-10-31.md)是当前交付状态。

## 产品定义与范围

让最亲近的几个人出现在彼此桌面上。对象为 2-9 人、邀请加入的封闭熟人小队。单人建队只是邀请准备；照片/组件活跃小队至少有两名成员。目标循环为“明确发给本队的一张照片 → 队友桌面看到 → 点击关联回拍 → 沉淀为小队记忆”。

第一阶段 iOS 优先，再补 Android/小米。五分钟往返是体验目标，需要另一位成员配合，不是必达时限。健身、旅行、美食等提供拍照与相约的理由；不扩大行情、公共基金审批、健康报告等首轮投入。

## 导航、身份与受众

| 入口 / 对象 | 规格 |
| --- | --- |
| 会话 | 小队会话列表与消息；照片、卡片、文字在同一时间线；计划讨论独立线程 |
| 小队 | 当前队、成员/邀请、共同计划、桌面组件设置；目标增加同源照片墙 |
| 计划 | 关联 Squad 的计划/任务；共同或仅自己可见；模板仅预填类别/标题 |
| 我的 | 账号、数据工坊、本机记录、通知、外观、帮助与退出 |
| captain/member | 队长管理邀请/成员与共享权限；成员参与并管理本人私密数据。角色不赋予读取他人 PrivateAsset 的权利 |
| 普通照片 | P0 明确发送给当前全队；不借用原素材 private/selected 分享通道扩大受众 |
| 既有私密素材/计划 | 保留 owner-only 或明确选择的接收者；切队、模板或照片功能不能改变其可见性 |

## S01 邀请与首次往返

1. 创建 Squad，或打开邀请/输入邀请码；登录后恢复合法的原邀请。
2. 服务端校验邀请、角色、成员身份及 9 人上限。过期、满员、已加入分别反馈。
3. 引导自愿绑定小队组件，再由用户在系统主屏幕添加；可跳过，不阻止 App 内收发。
4. 在该队拍摄/选图，预览后明确点击“发到「队名」”。
5. 另一成员看到照片，点击进入原队/原照片的回拍入口，再明确确认发送。

完成验收必须是不同作者的真实照片往返。教程打开、组件 reload 请求、推送回执不能单独算“看见”。

## S02 照片来源、确认与发布

| 项目 | 产品合同 |
| --- | --- |
| 来源 | 单张系统相机或系统选图；不强制文案、美化、通讯录或连续相册授权 |
| 净化 | 派生 JPEG，长边最多 1600 px、最多 2 MiB；去除原始 EXIF/GPS 等元数据；服务端重新校验/净化 |
| 确认 | 明示队名和受众；未确认不上传，取消不发布；模拟器相机不可用可给出状态并保留选图入口 |
| 待发 | 只有确认后的内容加密持久化；绑定原账号、原 Squad、父消息和 nonce；换账号不迁移给新账号 |
| 重试 | 原 nonce 对应同一冻结内容；服务端成功而响应丢失时查回身份，不能重复生成消息；换图需新确认 |
| 读取 | 私有媒体网关按当前普通用户权限验证；不使用公开 bucket、永久可读地址或把服务端 Key 放客户端 |
| 撤回 | 作者撤回留下墓碑及关系；后续读取拒绝，异步清理对象。不能承诺收回他人已保存的截图 |

拍摄时间不决定连续统计归属；发布时使用服务端时间。客户端断网与 iOS 结束进程不能被描述为仍会保证后台上传。

## S03 照片聊天与照片墙

照片消息是唯一事实源，照片墙只做按当前 Squad 的分页视图。照片、作者、撤回/隐藏状态与回复引用必须在会话和墙一致。墙不另建评论、点赞或发布系统。

回拍保存父消息身份；父子必须同队、同线程并可访问。父照片撤回/隐藏/无权时阻止回拍，给出中文状态，不自动改发到别队或悄悄变成无关联照片。文字回复保留明确关联。

不增加点赞数、成员贡献榜、跨队推荐或“谁还没发”的群体催促。已有 Social 及其私密/指定受众数据不隐式迁移进照片墙。照片墙网格与详情定位目前仍待实现。

## S04 iOS 桌面组件

| 项目 | 产品合同与当前边界 |
| --- | --- |
| 基础绑定 | 一个免费绑定队；系统多个实例共享它。本轮不做多个实例各绑不同队 |
| 预览 | 默认关闭；更换绑定会清原照片并关闭预览；开启控件明示设备旁人也可能看到 |
| 展示 | 最新可见照片、队名与最少回拍提示；中、小两种尺寸。空、隐藏、失败、到期、登录失效有占位 |
| 副本 | 受保护 App Group 派生 JPEG，最多 15 分钟且不超过有效会话/JWT；不存 refresh token 或私钥 |
| 权限 | 普通用户成员/消息验权；版本单调；旧绑定/账号/在途结果不得覆盖新状态 |
| 点击 | 固定 Squad/绑定/账号作用域，照片有效时携带父消息；进入 App 后重新校验，不能以当前选中队替代 |
| 刷新 | 前台更新和后台提示请求 WidgetKit 更新；实际绘制由系统调度，不能承诺每次立即或必达 |
| 安全 | 关闭预览、退出/换账号、失权等清副本；远端设备和系统快照仍需平台验收，不承诺瞬时擦除 |

原生后台只使用短期普通访问材料；需要 SDK 恢复时与现有 engine 协作，在原通知预算内处理。无第二认证引擎，不把高权限密钥下发扩展。当前尚无 APNs 平台投递通过证据。

## S05 已读、隐藏与举报

已读只在当前会话前台、窗口聚焦且最新消息实际可见时推进；照片还需实际解码。后台取图、桌面绘制、照片墙缩略图和历史滚动不等同已读。只有作者查看本条成员明细，加入前消息不参与统计。当前默认关闭 `ENABLE_CONVERSATION_READ_RECEIPTS`，剩余矩阵通过后再决定启用。

接收者隐藏只影响本人；不能替作者撤回。举报选择受控原因并再次确认，同时对本人隐藏；不复制原图进举报案例，不把举报者或案例展示给队友。提交功能已有，人工处置闭环仍待演练。

## S06 小队连续出现与周回顾（待实现）

- 队日首轮固定 Asia/Shanghai，UTC 存储、服务端计算。
- 一天任一有效成员成功发布一张普通照片或回拍即计入；文字、草稿、失败上传不计，同日多张不累加天数。
- 离线补发按实际服务端发布日，不修改手机时间或 EXIF 补签。今日结束前不判断断签；断后温和重新开始。
- 撤回某日最后一张有效照片需重算；历史贡献不直接用当前成员集合覆盖，离队者身份展示须受权限约束。
- 基础周回顾由用户主动打开，仅从当前可见、已分享、未撤回/隐藏照片生成；不读取私密资产/原始健康/私密计划，不自动外发。

全员到齐日、月年回顾、视频、付费外观与存储权益后置。免费核心包括建队/邀请/拍摄/相册/回复/基础墙/一个基础组件/基础连续/周回顾；其中尚未实现的能力不因“免费范围”而自动变成现有功能。当前没有订阅支付交付。

## S07 数据与隐私边界

原始个人素材优先留本机；必要云端摘要 owner-only。用户逐次选择、编辑、预览、确认受众后分享静态快照。健康敏感字段默认不选、不持续同步。普通照片的派生图上传例外不改变活动卡本机 PNG 与原始记录的限制。

PublicFund 为共享基金，PrivateAsset 只本人可见；队长不得越权。精确路线每卡单独确认并端到端加密，服务器不持有明文轨迹与私钥，不随普通照片明文上传或进入组件。所有云端业务同时执行 GRANT 与 RLS。

## S08 质量、度量与发布门

每条流程覆盖 loading/empty/error/success、取消、无权、账号切换、长中文、小屏及大字体。离线、副本到期、进程回收、强退和锁屏分别记录；Android 无 GMS 与 iOS 单独验收。

七天观察使用固定小队 cohort，至少记录邀请/加入、照片发布、不同作者回拍、组件入口打开。区分刷新请求、平台接受、设备取图、实际展示和点击；事件不含图片/正文/对象地址/精确位置。当前最小归因和 cohort 系统未完成。

核心观察为小队连续三天有照片、至少一次不同作者照片回拍、至少一次组件带来的 App 打开；同时保留失败样本、两位发照者比例与设备分层。不能用个人 DAU 或一个组件截图替代七天验证。

正式内测门包含：真实设备照片往返、签名/APNs、撤权与私密隔离反例、缓存与对象清理、人工举报处置、发布配置/远端 CI 与 TestFlight。当前尚未全部通过；逐项状态与证据见[功能完成情况](squadly-feature-status-2026-10-31.md)。
