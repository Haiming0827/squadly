# F04 本机运动记录与来源适配

## 职责和接口

本模块只为本人取出／补正**用户主动选择的一条真实跑步或徒步记录**，返回带来源与字段缺失状态的本机私有记录；不负责发布、群内同步或云端健康快照。`ActivitySource` 目前由手工、Apple HealthKit、本机 GPX／TCX／带时间 KML 文件适配器实现；小米和华为账号或端侧直连仍待平台准入。原始记录与精确轨迹不上传，文件解析结果暂存进程内存；卡片模块只能通过 domain 用例取得用户选定内容。

## 字段与口径

| 必有字段 | 可缺失字段 | 规则 |
| --- | --- | --- |
| 运动类型、发生日期／时区、距离、时长、配速 | 心率、体重、睡眠、精确轨迹 | 显示原始来源与手工补正标记；单位换算、配速计算和异常值有纯 Dart 测试。缺失不写 0，也不凭其他成员数据补齐。 |

体重和睡眠是独立观测，不天然属于单次运动；与运动的时间关联及对外显示方式属于 D04，未定前只在本人本机上下文中呈现，不组成“同一次运动事实”。

## 代码落点与平台门槛

当前实现进度（未完成真机验收）：`AppleHealthActivitySource` 已通过 `health` 插件接入 iOS 运动记录读取，卡片编辑页可以主动选择近 90 天的一条跑步／徒步记录。读取精确路线是独立方法，仅在选中记录后请求权限，并以 workout UUID 关联；卡片页已有默认关闭的路线分享开关和逐卡加密确认。GPX、TCX 和带时间戳的 KML `gx:Track` 文件可本机选择、解析、单条选择并在用户选中后单独读取路线；TCX 轨迹点有效心率求平均后填入本机草稿，分享复选框仍默认关闭。普通 KML `LineString` 只有坐标而缺少活动时间，不能凭空补造日期／时长，当前明确拒绝作为完整运动记录导入。解析器只经合成格式样例测试，尚未在华为导出的真机文件、HealthKit 授权、路线返回或系统文件选择器验证。小米导出归档格式尚待去标识化样例；直接账号连接仍待平台准入。

用户主动选择的 GPX、TCX 或 KML 轨迹文件可作为 Android／iOS 的**本机文件导入备用路径**。GPX 解析 `trk/trkseg/trkpt` 中的坐标与时间，读取有效 `hr` 扩展；TCX 解析 `Activities/Activity/Lap/Track/Trackpoint`，使用时间、位置、累计距离和心率样本；KML 仅接受带时刻和匹配坐标的 `gx:Track`，按标准规定的并行数组顺序配对时间与位置。无时间戳的 KML `LineString` 不足以还原运动日期／时长，因此必须拒绝，不填入当前日期或虚构时长。有效心率样本求平均；缺失／超范围则保持缺失。导入记录时，UI 可预填心率供用户核对，但“分享平均心率”仍默认关闭。运动类型由用户明确选择“跑步／徒步”，距离按格式中的可信累计值或分段轨迹估算，时长按首末时间计算，均可手工补正。体重、睡眠不从轨迹文件猜测。XML 仅限 5 MiB／5000 点；拒绝 DTD／实体声明。不上传源文件、文件名或原始轨迹。选中记录后才允许单独读取路线；多段轨迹可用于距离／时长，但不错误桥接为一条“精确路线”，故不开放其路线分享。已确认的单段路线分享仍需 F08 逐卡确认和端到端加密。

平台导出范围需准确表述：Apple 由 iOS HealthKit 读取用户选定的运动；华为官方说明支持导出运动路线，并在部分地区列出 GPX／TCX／KML 格式。首版解析 GPX、TCX 和含时间的 KML `gx:Track`；若华为导出的 KML 仅含无时间 `LineString`，用户需改导 GPX／TCX，或通过本机手工补正日期、距离与时长后使用不含精确路线的卡片流程。小米官方资料说明可从 Xiaomi Account 下载 Mi Fitness 云端运动健康数据，但没有公布稳定的文件 schema，当前不解析该归档，也不抓取私有数据库。实现小米归档解析前需要一份去标识化样例并确认格式稳定。

[GPX 1.1 轨迹结构](https://www.topografix.com/gpx/1/1/) · [Garmin TCX v2 schema](https://www8.garmin.com/xmlschemas/TrainingCenterDatabasev2.xsd) · [OGC KML 标准](https://docs.ogc.org/is/12-007r2/12-007r2.html) · [小米 Mi Fitness 数据导出说明](https://www.mi.com/global/support/article/KA-11566/) · [华为路线导出说明](https://consumer.huawei.com/jp/support/content/ja-jp15947057/)。

- 新建 `features/activity_import/{domain,data,presentation}`；本地结构化缓存按仓库约定使用 Drift（若实际依赖／生成链受限，先做可测试的本机 adapter 并记录过渡方案）。现有 `fitness` 打卡与 `health_snapshots` 不是原始运动记录库，不能直接复用为公开同步。
- 当前 `health 13.3.1` Android 插件的最低系统版本为 API 26，原项目为 API 24；为保持同一 Flutter 构建可编译，Android 应用最低版本提升到 26（Android 8）。这仅是包依赖门槛，不表示无 GMS 小米已支持 Health Connect／小米运动健康。低于 Android 8 的设备将无法安装新版 App，首轮测试机须核对系统版本。
- iOS 原生适配请求 HealthKit 逐类型授权，处理未授权、撤销及后台不可读；不得把“未读到”解释成“用户没有该数据”。
- 小米端侧适配先在**实际型号和 HyperOS 版本**探测 HealthKit 系统服务，再做开发者服务／Scope 审批、包名签名和用户授权；不满足则明确显示不可用并允许手工录入。[官方限制](https://dev.mi.com/xiaomihyperos/documentation/detail?pId=2332)
- 华为适配先核实 Health Kit 权益、机型、可读字段及数据是否能保持严格本机处理；未完成不得用“已连接”视觉文案。禁止抓取其他 App 的私有数据库或以云端厂商 OAuth 暗换本机原始数据承诺。

## 测试和排错

用真实但用户自选的一条记录核对运动类型、距离、时长与配速；覆盖可缺失字段、手工补正、授权拒绝／撤销／来源不可用／同一记录重复读取。故障按设备支持 → 平台服务与开发者审批 → 用户 Scope → 原生返回 → 统一字段映射 → 本地缓存 → 编辑 UI 逐层定位。真机报告仅写是否匹配，不记录健康值和坐标。
