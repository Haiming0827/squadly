# 小队会话管理：问题分析、产品规格与测试手册

日期：2026-11-03。实现以本次源码和[专项设计](../modules/conversation/conversation-management-design.md)为准。

## 原因

会话详情由首页直接创建独立页面，之前只接入消息时间线，没有连接小队管理；已有 Squad.avatarUrl 仅用于读取，没有受控更新能力。会话列表的首字头像、搜索和三个消息状态筛选也没有个人会话偏好数据支撑。因此缺少设置入口、头像修改、会话备注、置顶和常用排序是产品闭环未补齐。

## 本次规格

| 功能 | 交互与规则 | 数据可见范围 |
|---|---|---|
| 会话设置 | 进入小队会话，点击右上角省略号 | 当前小队 |
| 会话备注 | 最多 40 个字，留空恢复小队名称；搜索同时匹配备注和原名 | 仅本人；不改变全局昵称 |
| 置顶会话 | 在设置页打开开关后保存 | 仅本人 |
| 常用小队 | 页面上方圆形头像横排；置顶优先，然后最近 7 天打开频次、最近打开时间 | 本人的活跃小队，不包含计划讨论 |
| 主列表排序 | 置顶小队在前，同组保持最新消息顺序 | 仅本人 |
| 共享头像 | 队长从系统相册单次选图，预览后保存；可恢复默认头像 | 当前小队全员 |
| 共享名称与简介 | 队长修改名称（1–40 字）和简介（最多 200 字） | 当前小队全员 |
| 成员管理 | 设置页展示成员与角色，提供已有小队管理入口 | 原有邀请、移除、转让和人数权限继续生效 |
| 筛选菜单 | “会话”左侧图标，选择全部、小队会话、计划讨论、已置顶、有消息、暂无消息 | 只筛选本人可访问的列表 |

常用栏只有真实打开过或手动置顶的小队；新账号刚开始为空，进入一次小队后会出现。取消置顶不一定让该小队离开常用栏，因为最近访问仍可能满足条件。打开频次不对队友公开，不作为社交排名。

参考图中的未读、@我、云文档和已完成没有对应完整业务数据，本轮不增加这些菜单项。计划讨论继续遵守原有计划的 Squad/指定成员可见范围。

## 权限与实现

- 新增 `conversation_preferences`、`conversation_open_days`，绑定当前 `squad_members.id`，RLS 只允许本人读取；离队/被移除时级联清理，重新入队不复活旧设置。
- 备注、置顶和访问通过受控 RPC 写入，从登录 JWT 得到本人身份，不能代填其他账号；最近 7 天按上海时区自然日计算，单日计数最高 100。
- 小队资料通过队长限定的 `update_squad_profile` RPC 更新，客户端对 squads 仍只有 SELECT 权限。
- 头像复用系统照片来源，居中裁成 96×96 PNG 并重新编码；不携带原图元数据。缩略图不超过 48KiB，通过现有 Squad RLS 存在共享资料中，不使用公开图片桶或外部链接。服务端校验大小、文件头及尺寸，图片头检查不等于完整内容安全检测。
- 演示模式提供账号及 membership 隔离的本地备注/访问记录和队长校验；真实模式使用普通 CloudBase 用户 JWT。

主要代码：`lib/app/providers/conversation_customization_providers.dart` 为组合根；conversation/domain 定义个人设置模型/接口；conversation/data 和 squad/data 封装 RPC 与头像准备；conversation/presentation 实现设置页、筛选和常用栏。数据库版本为 `20261103000100_conversation_customization.sql`。

## 如何实际测试

Device Hub 中的普通 App `com.squadly.squadly` 已更新，A 为 iPhone 17 Pro，B 为 iPhone 17；保留原账号和数据。验收新建的“会话设置验收”小队，避免改动原照片小队。

1. A 在会话页查看“我的置顶验收”，点击列表或常用圆形头像进入；右上角省略号打开“会话设置”。
2. 修改“会话备注”、打开/关闭“置顶会话”，点击“保存个人设置”。返回后确认列表、会话标题、常用栏和备注搜索生效。B 应仍显示自己的“我的成员备注”。
3. A 选择头像，只在本机预览时 B 不变化；点击“保存小队资料”后，B 回到会话列表下拉刷新，应看到新共享头像。取消相册选择应保留当前头像；“恢复默认”也需保存后生效。
4. A 修改小队共享名称并保存；B 下拉刷新后可见。B 打开设置，只能改自己的备注/置顶，看不到头像和共享名称的编辑控件。
5. 会话页点击标题左侧筛选图标，逐项检查“已置顶、小队会话、计划讨论、有消息、暂无消息”；已置顶只筛主列表，常用栏保持稳定。搜索原小队名和个人备注都能命中。
6. 进入“管理小队成员”，检查邀请、角色和已有成员操作。不要为测试移除原小队成员；退出/重新入队清理已由本地 SQL 验证，云端该破坏性场景未在原小队执行。

其他环境需先完成 migration 22 的部署，否则设置会显示加载失败；不要用演示模式替代真实后端验收。系统照片来源目前只在 iOS 接入，Android 的原生头像选择仍待接入；备注、筛选、置顶和权限接口为共享 Flutter 实现。
