# F05 两类卡片、发布快照与本机渲染

## 职责和接口

卡片模块拥有运动记录卡、群聊内容卡的草稿、模板版本、字段／受众确认、不可变发布快照和本机 PNG 渲染。小接口示意：`draftFromActivity`、`draftFromMessages`、`confirmAndPublish`、`renderLocalImage`。会话模块只拿到发布后的卡片 ID；来源模块不直接发群聊。

## 数据流与待决点

```text
本人本机记录 / 已授权的小队消息
  → 本机草稿和编辑 → 发布前预览（来源、时间、字段、受众）
  → 明确确认 → 服务端卡片快照 + 同事务卡片消息
  → 两端按 templateId + templateVersion + 快照重绘本机 PNG
  → 相册 / 系统分享（F06）
```

- 图片字节、草稿、完整来源记录及明文精确轨迹不得上传。用户逐字段确认的健康数值可在卡片快照中；敏感字段默认不选。精确路线走 F08 的每卡端到端加密密文，不放进普通 JSON 快照。
- 运动卡字段应包括已确定的运动类型、日期、距离、时长、配速；心率、体重、睡眠、精确轨迹即使有值也默认不选，发布者逐项勾选，缺失不虚构。路线勾选后必须在发布前确认当前成员密钥齐备并完成本机加密；来源标签与手工补正标记不能伪装成“平台已验证”。
- 首轮群聊卡只允许发布者手选本人发送的 1–6 条文字消息；客户端和数据库必须一致拒绝第 7 条。自动摘要及引用他人内容的对外分享许可仍是 D05，不预设可以自动总结全群。
- 发布快照与模板版本一经发布应足以在另一台设备重绘同一内容；删除本机缓存可重绘，撤回卡片只能影响 Squadly 内可见性，不能收回已经发出的微信图片。
- 发布请求若因网络中断而结果不明，同一界面内或重启后重试**未改动**的快照与路线时复用卡片 ID、消息幂等键及原加密密文；改动字段或路线必须作为新请求并重新确认。不得在每次重试时生成新卡片 ID 后把重复发布伪装成成功。本机待发载荷用设备密钥加密持久化，服务端确认后删除；磁盘重开、跨控制器恢复已有本地测试，iPhone／小米断网杀进程真机验收仍待完成。

## 代码落点与调试

新建 `features/cards/{domain,data,presentation}`；从 `features/social/presentation/screens/share_composer_screen.dart` 和 `data_story_card.dart` 迁移交互／视觉，避免在 widget 中直接访问 DemoAppStore 或数据库。测试包括字段白名单、模板版本兼容、两端一致内容、PNG 本机生成、原子发布失败回滚、RLS 和发布后撤回。故障按草稿字段 → 用户确认快照 → 服务器记录／消息外键 → 模板版本 → 本机绘图逐层定位。
